# Database regression suites

These SQL suites create fictional users, workspaces, records, sessions and an
unusable MFA factor. They test writes, deletes, role policies and grants; they are
**not read-only probes**. No real Auth email or external enrollment call is made.

For a standalone run, review the three migrations in the documented order
(members/roles, dashboard/finance, Account), then run each corresponding `.test.sql` as the database owner
with stop-on-error enabled. Each suite starts a transaction and finishes with
`ROLLBACK`. Keep the complete suite together; do not execute selected write lines
or commit its fixtures. Fixture mutations use reserved IDs or the
fixture workspace, including transaction descriptions that could occur elsewhere.

PostgreSQL `BEGIN` statements do not create nested transactions. Each migration
has its own `BEGIN`/`COMMIT`: wrapping unchanged migration files in another
transaction does **not** make a rollback rehearsal. A migration's `COMMIT` commits
the transaction, and a later test-suite `ROLLBACK` does not undo that schema/RLS
change. Do not concatenate the original files under an outer rollback and assume
the project is restored.

## Completed current-project rehearsal

On 18 November 2026, all three suites passed on the actual current PostgreSQL 17.12
project using a separately authorized and reviewed batch generated by
[`tools/current-project-rehearsal.mjs`](../../tools/current-project-rehearsal.mjs).
The final finance-extended batch SHA256 was
`2959192d80ab31b5fa9ebd63712911888b4e5a82393b5e92b2c4c1d18858bb4f`.
It included complete 1,005-row totals, server-recomputed month close, filtered
search, role/farm-scope rejections and the existing members/dashboard/Account cases.

That generator does not connect to a database. It verifies the six source files,
removes their standalone transaction wrappers, and produces one outer transaction
with no inner commits, three fixture-isolating savepoints and a final rollback.
The reviewed batch checks reserved-ID collisions and trigger definitions, uses
short lock/statement/transaction timeouts, resets role/claims between suites and
forces deferred foreign-key checks before each PASS. The SQL editor's stop-on-error
behavior was checked before execution. Do not bypass these guards or treat an
arbitrary concatenation as equivalent.

The batch, source-hash manifest, execution evidence and before/after fingerprints
are retained outside this public repository in the workspace's
`fieldwork-export-checks` directory. Postflight matched all **1,299 catalog items /
MD5 `992fc360118daa1d8f2398d90ba4f75b`**, and the scan of 25 fixture prefixes found
no remaining IDs. **No proposed migrations, grants, policies or fixture rows were
retained.** Installation remains a separate decision. Detailed Auth/security
configuration is not published here.

Audit triggers consume `audit_log` identity values. Sequence advances are not
rolled back, so even rolled-back fixtures can leave ID gaps. Do not reset a live
sequence to conceal gaps; that can conflict with concurrent records. Normal
database logs also survive rollback. Rollback does not avoid temporary locks while
a test or migration runs.

The 44 anonymous/nonmember read-only checks were a separate baseline probe. The
successful SQL rehearsal verifies these single-connection fixture cases; it does
not establish real Auth email/OAuth/TOTP/deletion, browser/REST integration or
concurrent-session behavior. Local simulated permissions and JavaScript checks
are separate evidence. Never rerun the original `db/schema.sql` over existing
farm data.
